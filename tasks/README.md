# Задачи

Как мы работаем с задачами — коротко и без сюрпризов.

## Где что лежит

- **[`board.md`](board.md)** — вся доска: ID, раздел ТЗ, этап, исполнитель, ветка, статус.
- **`T<этап>.<номер>-<ключ>.md`** — карточка задачи: что сделать, чек-листы бэкенда/фронтенда, приёмка.
- Шаблон для новой задачи — [`_template.md`](_template.md).

## Как взять задачу

1. Открываем `board.md`, берём задачу своего этапа с выполненными зависимостями.
2. Переводим статус в `in progress` (в board.md или в GitHub Projects — там же, где команда договорилась).
3. Ветка: `git switch -c feat/T2.1-catalog`.
4. Делаем по чек-листам карточки. Если чек-лист расходится с реальностью — правим карточку, а не молчим.
5. Открываем PR по шаблону, ставим ревьюером второго участника.
6. После аппрува — squash-merge, статус `done`, галочки в карточке.

## Когда задача считается готовой

Все пункты «Приёмка» выполнены **и**:

- [ ] работает и в API, и в интерфейсе (не только бэкенд «на будущее»);
- [ ] есть тесты на серверную логику и права доступа;
- [ ] `docs/api.md` обновлён, если менялся контракт;
- [ ] нет `console.log`, `print`, закомментированного кода и секретов;
- [ ] проверено на ширине 360 px, если задача трогает интерфейс;
- [ ] CI зелёный.

## Правила игры

- **Не начинаем задачу, если её зависимость не в `main`.** Если очень надо — договариваемся о контракте и пишем код на заглушке.
- **Не раздуваем PR.** Больше ~400 строк — режем на части.
- **Не трогаем чужую зону без предупреждения.** Файлы чужой задачи — только после сообщения в чат.
- **Блокер дольше дня** — сообщаем сразу, а не в день сдачи.

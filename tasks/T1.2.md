## Что нужно получить

Гость спокойно читает каталог, карточки и публичные рецензии, а любые изменения доступны только после входа.

## Бэкенд

- [x] Зависимости FastAPI: `get_current_user` (401), `get_optional_user` (гость или пользователь).
- [x] `require_role` / уровни ролей для будущих модераторов и админов.
- [x] Блокировка (`is_blocked`) закрывает доступ даже с валидным токеном.
- [x] Тест-матрица: гость × пользователь × (закрытый эндпоинт); расширяется вместе с новыми разделами.

## Фронтенд

- [x] Кнопки изменения данных у гостя не рисуем, но и не прячем смысл: показываем «Войдите, чтобы добавить на полку».
- [x] Глобальный обработчик 401: очистка токена и редирект на `/login`.

## Приёмка

- [x] Гость открывает каталог, карточку и публичную рецензию без входа.
- [x] Любой `POST/PATCH/DELETE` без токена даёт 401, с токеном — 200/201.
- [x] Заблокированный пользователь получает 403 и сообщение «Аккаунт заблокирован».

## Заметки

Это фундамент для всех следующих задач — не откладываем в конец этапа.

Бэкенд и фронтенд сделаны в одном модуле: `feat/T1.2-access` (deps, 401/403, `require_role`, `tests/test_access.py`) и `feat/T1.1-auth-ui` (глобальный 401, гостевая подсказка). Смержено в `main` 28.10.2026. Матрица по разделам расширяется в PR этих разделов (каталог — T2.1, рецензии — T4.3).

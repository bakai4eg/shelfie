## Что нужно получить

Гость спокойно читает каталог, карточки и публичные рецензии, а любые изменения доступны только после входа.

## Бэкенд

- [x] Зависимости FastAPI: `get_current_user` (401), `get_optional_user` (гость или пользователь).
- [x] `require_role` / уровни ролей для будущих модераторов и админов.
- [x] Блокировка (`is_blocked`) закрывает доступ даже с валидным токеном.
- [ ] Тест-матрица: гость × пользователь × (закрытый эндпоинт) для каждого раздела.

## Фронтенд

- [ ] Кнопки изменения данных у гостя не рисуем, но и не прячем смысл: показываем «Войдите, чтобы добавить на полку».
- [ ] Глобальный обработчик 401: очистка токена и редирект на `/login`.

## Приёмка

- [ ] Гость открывает каталог, карточку и публичную рецензию без входа.
- [ ] Любой `POST/PATCH/DELETE` без токена даёт 401, с токеном — 200/201.
- [ ] Заблокированный пользователь получает 403 и сообщение «Аккаунт заблокирован».

## Заметки

Это фундамент для всех следующих задач — не откладываем в конец этапа.

Бэкенд реализован в ветке `feat/T1.2-access` (поверх `feat/T1.1-auth`): `tests/test_access.py` проверяет 401 у гостя, 200 у пользователя, 403 у заблокированного, 401 у просроченной и отозванной сессии, а также матрицу `require_role`. Матрица по разделам расширяется в PR этих разделов (каталог — T2.1, рецензии — T4.3): защищённых маршрутов, кроме `/auth/*`, пока нет. Фронтенд-часть — зона Эльвины.

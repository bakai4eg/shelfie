## Что нужно получить

Модератор разбирает очередь, скрывает или удаляет нарушающий контент, и это сразу исчезает из выдачи и ленты.

## Бэкенд

- [x] `GET /moderation/reports`, `POST /moderation/reports/{id}/resolve` (reject/hide/delete + причина).
- [x] `POST /moderation/content/{type}/{id}/hide|delete` с каскадом: рецензии, оценки, полки, позиции списков, жалобы.
- [ ] Каскад на комментарии, лайки и события ленты — подключить вместе с T4.4, T5.3, T5.4 (в `services/cleanup.py`).
- [x] Очередь локальных карточек: `GET /moderation/cards`, `approve`, `reject`.
- [x] Запись каждого решения в `audit_log` (готовим таблицу здесь, панель — в T5.2).

## Фронтенд

- [x] Раздел `/moderation`: очередь жалоб с контекстом (что за материал, кто пожаловался, причина).
- [x] Кнопки «Отклонить», «Скрыть», «Удалить» с обязательным подтверждением и причиной.
- [x] Очередь локальных карточек с предпросмотром и решением.

## Приёмка

- [x] Скрытая рецензия исчезает из карточки и профиля (лента — после T5.4), но остаётся в БД со статусом.
- [x] Удаление уносит связанные данные и жалобы — проверено тестом (комментарии и лайки — после T4.4 и T5.3).
- [x] После подтверждения локальная карточка видна гостю.
- [x] Каждое действие модератора попадает в журнал.

## Что нужно получить

Пользователь создаёт аккаунт по логину и e-mail, входит и остаётся в системе без повторного ввода пароля, пока жива сессия.

## Бэкенд

- [x] Модели `users`, `sessions` + миграция Alembic.
- [x] Хэширование пароля (bcrypt), проверка уникальности логина и e-mail.
- [x] `POST /auth/register`, `POST /auth/login`, `POST /auth/logout`, `GET /auth/me`.
- [x] Выпуск JWT с `jti`, запись сессии в БД, проверка сессии на каждом запросе (ADR 0001).
- [x] Валидация: логин 3–32 `[a-zA-Z0-9_]`, пароль ≥ 8, 409 на занятый логин/e-mail, 401 на неверную пару.

## Фронтенд

- [x] Страницы `/register` и `/login` с валидацией на клиенте и разбором ошибок API.
- [x] `AuthProvider`: загрузка текущего пользователя, вход, выход, хранение токена.
- [x] Защищённые маршруты и редирект на `/login` при 401, возврат на исходную страницу после входа.

## Приёмка

- [x] Регистрация → автоматический вход → перезагрузка страницы сохраняет сессию.
- [x] Выход отзывает сессию: старый токен даёт 401.
- [x] Повторная регистрация того же логина/E-mail возвращает 409 и понятное сообщение в UI.
- [x] `pytest` покрывает успешный вход, неверный пароль, дубль логина.

## Заметки

Пароль в логи не писать. Токен — только в одном месте (`lib/auth.ts`), остальной код ходит через хук `useAuth`.

Бэкенд и фронтенд сделаны в одном модуле: `feat/T1.1-auth` (модели, миграция `0001`, сервис, 20 тестов) и `feat/T1.1-auth-ui` (страницы, `AuthProvider`, защищённые маршруты). Смержено в `main` 28.10.2026.

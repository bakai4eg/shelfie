# 0001. JWT + таблица сессий

- **Дата:** 2026-10-21
- **Статус:** accepted
- **Участники:** Бакай, Эльвина

## Контекст

ТЗ 4.2.1 требует работы без повторного ввода пароля в течение срока сессии, ТЗ 4.2.4 — завершения действующих сессий при смене пароля, ТЗ 4.6.4 — невозможности входа для заблокированного пользователя. При этом нужен простой вариант для студенческого проекта на FastAPI + SPA.

## Варианты

1. **Серверные сессии в cookie** — просто отзывать, но требует CSRF-защиты и аккуратной настройки cookie между `localhost:5173` и `localhost:8000`.
2. **JWT без состояния** — просто, но нельзя отозвать токен до истечения срока: смена пароля и блокировка не сработают мгновенно.
3. **JWT + запись `jti` в `sessions`** — токен в заголовке `Authorization`, отзыв через БД.

## Решение

Вариант 3. Токен живёт 24 часа, `jti` хранится в `sessions`; проверка каждого запроса = подпись + наличие неотозванной сессии. Смена пароля, блокировка и logout помечают сессии отозванными.

## Последствия

- Один дополнительный запрос к БД на авторизованный запрос — для учебной нагрузки несущественно.
- Фронтенд хранит токен и подставляет его в заголовок; 401 → выход и редирект на вход.
- Нужна миграция `sessions` и тесты на отзыв сессий (смена пароля, блокировка).

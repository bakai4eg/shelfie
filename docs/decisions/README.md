# Архитектурные решения (ADR)

Короткие записи о том, **почему** сделано именно так. Один файл — одно решение. ADR не переписываем: если решение изменилось, добавляем новый и помечаем старый как `superseded`.

## Список

| № | Решение | Статус |
| --- | --- | --- |
| [0001](0001-jwt-sessions.md) | JWT + таблица сессий вместо серверных cookie-сессий | accepted |
| [0002](0002-single-catalog-table.md) | Одна таблица `catalog_items` для книг, фильмов и сериалов | accepted |
| [0003](0003-external-api-cache.md) | Кэш внешних источников в собственной БД с TTL | accepted |

## Когда писать ADR

- выбрали библиотеку/подход, который затронет обоих;
- отступили от ТЗ (и почему это допустимо);
- решение можно пересмотреть через месяц и потом забыть причину.

Шаблон — [`template.md`](template.md). Файл называем `NNNN-короткое-имя.md`, статусы: `proposed`, `accepted`, `superseded`, `rejected`.
